# tests/

Automated tests for the scripts, run on your PC with Node, never in game. Design: [`docs/testing.md`](../docs/testing.md).

```powershell
npm test
```

Needs Node 22 or later (`node --version`). It prints one line per test and ends with the pass and fail counts; a failing
test prints what it expected and what it got. To run one file: `node --import ./tests/support/register.mjs --test tests/batcher.test.mjs`.

These are `.mjs` files, so filesync never pushes them to the game, and they have no RAM cost or `Requires` tag.

A test's name says what kind it is, and so what a failure means ([`docs/testing.md`](../docs/testing.md)):

| Tag | Pins | If it fails after a change |
| --- | --- | --- |
| `regression:` | a bug that was fixed | the bug is back: fix the code |
| `game:` | a formula or rule from the game's source | the code is wrong, unless the game changed |
| `choice:` | a default, threshold or wording we picked | update it if the change meant to change it |
| none | a rule the script promises | fix the code, or, if the rule changed on purpose, update the test and its name |

Every changed, removed or renamed test goes in the change report with its kind and why. Two helpers:

```powershell
npm run test:changed                 # tests changed since the last commit (or: npm run test:changed -- <git ref>)
npm run mutate -- hack/batcher.js    # flips conditions in a copy of the script; lists the ones no test notices
```

## Writing a test

- Import the script by its game path (`import { gymStep } from "/singularity/player-work.js"`); export the function from
  the script if it isn't yet. Build `ns` with `fakeNs({ files, ports, money, overrides })`.
- Use the real config (`loadConfig(fakeNs())`) and change only what the test is about, so the test follows the defaults.
- For a bug fix, write the test first, see it fail, then fix. Name it `regression: <what went wrong>`.
- Name the rule, not the inputs, and assert the rule: expected values from the inputs, config or game formula, with a
  message saying why. Tag `game:` when the numbers come from the game's source, `choice:` only when pinning a value is the point.
- Check that it protects something: `npm run mutate -- <script>` should list fewer survivors with the test than without.
